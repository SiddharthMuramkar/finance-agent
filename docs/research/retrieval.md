# RAG and stored data: Neon, pgvector, Pinecone, embeddings, citations

Research notes gathered on 2026-11-01. Prices, limits and terms change, so recheck before relying on them. This is not legal advice.

## Summary

Anthropic sells no embeddings API. Voyage's free 200M tokens dwarf the measured corpus (about 2.4-2.6M words, 3-4.5M tokens), so embedding cost is near zero. That corpus should fit Neon Free (1 GB) and Pinecone Starter (2 GB), by estimate. Pinecone still leaves a second store beside SQL, and its free tier is locked to us-east-1. Neon now offers BM25 and vector indexes, with hybrid done by fusion in SQL. Keyword-only retrieval is viable but somewhat weaker in one study and costs more tokens; no study tested this corpus. search_result citations work in Messages and Managed Agents; Tool Runner is confirmed only from SDK source, and Agent SDK docs do not list them. Contextual Retrieval is about $1-4 one-off on Haiku 5.5. On the user's question: nothing here forces a model choice now. Citations work on every active model except Haiku 3, so the model stays swappable. Retrieval studies do not show whether a cheaper model teaches well; that needs a side-by-side test.

## Options

### Neon pgvector plus native Postgres full-text search (tsvector, GIN, ts_rank), fused in SQL

- **Fit:** One SQL store for chunks, chats and progress. Standard Postgres, so it is portable off Neon. pgvector is confirmed on every plan. Exact vector scan needs no index at small sizes, though latency is unmeasured.
- **What would break it:** Neon says ts_rank lacks BM25 and corpus statistics, so keyword ranking may be weaker, and the BM25 evidence above would not apply. Query-time search depends on an outside embedding API. HNSW builds may be slow on a small compute. Ligature-corrupted PDFs hurt the keyword side.
- **Cost:** $0 on Neon Free if within limits. Embeddings about $0 inside Voyage's free 200M tokens. Neither is paid by Claude credits. Neon Launch has no minimum if limits are outgrown.

### Neon Lakebase Search hybrid (lakebase_vector plus lakebase_text BM25), fused with Reciprocal Rank Fusion in SQL

- **Fit:** One SQL store with real BM25 and vector search. Matches the hybrid pattern Anthropic and the finance benchmark found strongest. Keeps the same vector and tsvector column types as pgvector and native search. Indexes survive scale-to-zero. Reranking can be added later.
- **What would break it:** Free-plan availability is not stated in the docs read. Neon-specific extensions reduce portability. BM25 statistics lag until VACUUM after bulk loads. IVF recall at this small size is untested. Fusion SQL must be written, since there is no built-in hybrid function. Also depends on an outside embedding API at query time.
- **Cost:** $0 on Neon Free if available there. Embeddings about $0 inside Voyage's free tier. Optional rerank-3 is 200M tokens free, then $0.05 per million. Contextual Retrieval about $1-4 one-off on Haiku 5.5 from Claude credits.

### Neon BM25 only, with Claude writing the search queries and no embeddings

- **Fit:** Simplest stack: no embedding vendor, no vector index, and no outside API at query time. Anthropic suggests starting with agentic search, though for file-system agents. The AWS study supports viability at about 88-90%+ of RAG. Vectors can be added later to the same table if evals show a gap.
- **What would break it:** Paraphrases: both Neon and Pinecone document keyword search missing synonyms, and Buffett's metaphors may not match a beginner's words unless Claude bridges them. PDF corruption such as 'CreaAon' makes passages unfindable. Extra tool rounds add latency and Claude token cost. Ambiguous questions were a stated weakness. If lakebase_text is unavailable, it falls back to weaker ts_rank.
- **Cost:** $0 outside Claude on Neon Free. Extra Claude spend per turn from repeated searches, not measured for this project.

### Pinecone for retrieval plus Neon for stored data

- **Fit:** Managed vector and BM25 search with hosted embeddings and reranking under one API, and the corpus should fit Starter comfortably. Reasonable if retrieval is expected to grow far beyond this corpus. Neon is still needed because stored data goes in SQL.
- **What would break it:** Two stores to keep in sync, with no SQL joins between chunks and learner data. Starter is us-east-1 only. Monthly caps return 429 until the next month or an upgrade. 5M embedding tokens per month is barely above one full corpus embed. 500 rerank requests per month could run out with daily study. Stronger rerankers need Standard.
- **Cost:** $0 on Starter plus Neon Free. Builder is $20/month flat to change region; Standard has a $50/month minimum. Not paid by Claude credits, so it comes out of a separate budget.

## Findings

- Anthropic does not offer its own embedding model. Its docs say so directly and point to Voyage AI (by MongoDB) as one provider, while advising developers to assess other vendors too. Source: https://docs.claude.com/en/docs/build-with-claude/embeddings
- Voyage prices per million tokens: voyage-4-lite $0.02, voyage-4 $0.06, voyage-4-large and voyage-context-4 $0.12. Each has the first 200M tokens free per account. voyage-finance-2 is $0.12 with 50M free and is listed as previous generation. Reranking: rerank-3 $0.05, rerank-3-lite $0.02, 200M free. Free tokens do not apply to the Batch API. My arithmetic: 3-4.5M corpus tokens is about 2% of the free allowance, and under $0.55 at list price even on voyage-4-large. Standard rate limits (2000 RPM, 3-16M TPM) require adding a payment method: https://docs.voyageai.com/docs/rate-limits Source: https://docs.voyageai.com/docs/pricing
- Other embedding options, per million tokens. OpenAI text-embedding-3-small $0.02, 3-large $0.13. Google gemini-embedding-001 $0.15 and gemini-embedding-2 $0.20 (batch $0.075 and $0.10); Google's free tier is free of charge but content is used to improve its products (https://ai.google.dev/gemini-api/docs/pricing). voyage-4-nano is open-weight (Apache 2.0), self-run and not on the API (https://docs.claude.com/en/docs/build-with-claude/embeddings). Vercel's function bundle limit is 250 MB (https://vercel.com/docs/functions/limitations), which matters if query embedding runs inside a function. Neon AI Gateway embeddings need a paid plan with prepaid credits (https://neon.com/docs/ai/lakebase-search-get-started). None of these are paid by Claude credits. Source: https://developers.openai.com/api/docs/pricing
- Corpus measured directly. Buffett letters: 48 letters, 1977-2024, about 612k words. 1977-1997 are HTML; the 1998-2003 HTML pages are stubs pointing to PDFs; 2004-2024 are PDFs. Damodaran blog: 685 posts, 1,546,936 words, Sept 2008 to Oct 2026 (Blogger feed: https://aswathdamodaran.blogspot.com/feeds/posts/default?alt=json). Lecture notes, partly sampled: three spring-2026 valuation packets total 702 pages and 58k words (about 83 words per slide); four of the 100 webcast session PDFs had 870-1,368 words each. My estimate: 2.4-2.6M words in total, about 3-4.5M tokens at 1.3-1.75 tokens per word. The lecture share (0.2-0.4M words) is a guess because the corporate finance and investment philosophy packets were not measured. Source: https://www.berkshirehathaway.com/letters/letters.html
- Neon Free: 1 GB Postgres per project, 100 CU-hours per project per month (400 hours at 0.25 CU), 5 GB egress, 6-hour history window, 1 manual snapshot, scale-to-zero after 5 minutes that cannot be disabled, wake in a few hundred ms. Using up CU-hours or egress suspends compute until the next billing period; exceeding 1 GB blocks writes; data is not deleted. Launch has no minimum: $0.106/CU-hour, $0.35/GB-month, up to 7 days of history. My unmeasured estimate at 10k chunks with 1024-dim vectors: 41 MB of vectors (pgvector uses 4*dimensions+8 bytes, https://github.com/pgvector/pgvector), about 20 MB of text, about 100-200 MB with indexes. That fits, but the short history window is a risk for learner progress data. Source: https://neon.com/pricing
- Neon's current search product is Lakebase Search, built by Databricks and requiring Postgres 16+. lakebase_vector adds an IVF plus RaBitQ index (lakebase_ann) on the same pgvector types; lakebase_text adds a BM25 index (lakebase_bm25) on standard tsvector. There is no built-in hybrid function: you run both and fuse with SQL such as Reciprocal Rank Fusion. The BM25 index should be created after loading, and its statistics update at VACUUM (https://neon.com/docs/extensions/lakebase-text). Neon says native GIN with ts_rank lacks BM25 and corpus statistics. pg_search was retired from Neon on Sept 21, 2026 (https://neon.com/docs/extensions/pg_search), so older guides are stale. pgvector is on every plan (https://neon.com/docs/extensions/pgvector). Source: https://neon.com/docs/ai/lakebase-search
- Pinecone Starter: 2 GB storage, 2M write units and 1M read units per month, 1 GB egress, 5 indexes, 100 namespaces, AWS us-east-1 only. 5M embedding tokens per month per model; 500 bge-reranker requests per month. Hitting a monthly limit returns 429 (https://docs.pinecone.io/reference/api/database-limits/rate-limits). Builder is $20/month flat for other regions; Standard has a $50/month minimum. Pinecone's illustrative example: about 30K documents at 1024 dimensions supports about 15k searches per day. Upserts cost 1 WU per KB (https://docs.pinecone.io/guides/manage-cost/understanding-cost), so my estimate for 10k chunks is about 60k WU. Full-text BM25 indexes exist on all plans and one index can also rank semantically (https://docs.pinecone.io/guides/search/full-text-search). It would not replace the project's SQL store. Source: https://www.pinecone.io/pricing/
- AWS authors (preprint) compared an agent using only keyword tools (rga, pdfgrep) against vector RAG. The agent reached over 90% of RAG's metrics overall and 'consistently above 88%' average attainment, and was generally slightly below the baseline. Scoring was LLM-as-judge (RAGAS) on LlamaHub datasets with Claude 3 Sonnet. Stated limits: large documents, ambiguous queries, contextual nuance. This was grep over PDF files, not ranked BM25. Related: the IterKey abstract reports LLM keyword generation 5-20% above plain BM25 RAG and comparable to dense retrieval (https://arxiv.org/abs/2505.08450; read through a paper index, not arXiv directly). Source: https://arxiv.org/abs/2602.23368
- A preprint scaling study (July 2026) varied corpus size about 450-fold. A file-system agent led at the smallest tiers but used 39 times more query tokens at the study's fixed base set of documents. BM25 overtook it around 10M corpus tokens. Dense retrieval was efficient but less accurate. The authors conclude agentic reasoning works best after ranked discovery rather than in place of it. The measured corpus (3-4.5M tokens) sits below that crossover, but the dataset differs and only the abstract was read. Source: https://arxiv.org/abs/2607.26497
- The closest domain evidence is a preprint on financial QA over text and tables (23,088 queries, 7,318 documents). BM25 beat dense retrieval. Hybrid plus neural reranking was best (Recall@5 0.816, MRR@3 0.605). HyDE and multi-query expansion helped little for precise numerical queries; contextual retrieval gave consistent gains. These are numeric lookups over reports, unlike a beginner's conceptual questions, so transfer to this tutor is uncertain. Source: https://arxiv.org/abs/2604.01733
- Anthropic gives two different signals. Its agent article says semantic search is 'usually faster than agentic search, but less accurate, more difficult to maintain, and less transparent' and suggests starting with agentic search, adding semantic search only for speed or more variations. That advice is about file-system agents. Its Contextual Retrieval post found embeddings plus BM25 better than embeddings alone (https://www.anthropic.com/news/contextual-retrieval). Neither tested a finance tutor. Source: https://claude.com/blog/building-agents-with-the-claude-agent-sdk
- search_result blocks are part of the standard Messages API with no beta header, and work on all active models except Haiku 3, so retrieval code does not lock in a model. They can be returned from a custom tool or placed in a user message. Citations are off by default and all-or-nothing per request; content is text only, no images. cited_text is the full text of the cited block(s), so block size sets quote length, and the docs advise splitting content into logical blocks. Text placed in a content block becomes citable, so my inference is that generated Contextual Retrieval prefixes should stay out of returned blocks or they could read as Buffett's words. Managed Agents accepts them only in tool results such as user.custom_tool_result. Source: https://docs.claude.com/en/docs/build-with-claude/search-results
- Tool Runner (beta): the docs say a tool returns a string or content blocks '(text, image, or document blocks)', without naming search_result (https://docs.claude.com/en/docs/agents-and-tools/tool-use/tool-runner). The TypeScript SDK source types run() as string | Array<BetaToolResultContentBlockParam>; that union includes BetaSearchResultBlockParam (src/resources/beta/messages/messages.ts) and the runner passes content through unchanged. The Python SDK has the same union (https://github.com/anthropics/anthropic-sdk-python/blob/main/src/anthropic/lib/tools/_beta_functions.py). So it should work by code reading. It was not run against the live API. Source: https://github.com/anthropics/anthropic-sdk-typescript/blob/main/src/lib/tools/BetaRunnableTool.ts
- Claude Agent SDK custom tools: the handler's content array is documented as text, image, audio, resource or resource_link blocks. search_result is not listed and the page does not mention citations. Native citations through this path are therefore undocumented, which could affect the Sources panel if the loop is built on the Agent SDK. Source: https://platform.claude.com/docs/en/agent-sdk/custom-tools
- Citations cannot be combined with structured outputs: citations on search_result blocks plus output_config.format returns a 400 error, and prompts asking for only JSON may yield few or no citations. My inference: chart and calculator payloads would need to go through tool calls rather than a JSON-formatted reply in the same request. cited_text does not count toward output tokens; enabling citations slightly raises input tokens. Source: https://docs.claude.com/en/docs/build-with-claude/citations
- Contextual Retrieval prepends 50-100 tokens of generated context to each chunk before embedding and BM25. Top-20 retrieval failure fell from 5.7% to 3.7% (contextual embeddings), 2.9% (plus contextual BM25) and 1.9% (plus reranking). Domains tested were code, fiction, arXiv and science papers, not finance. Published cost is $1.02 per million document tokens using Claude 3 Haiku. My recalculation with current prices (https://docs.claude.com/en/about-claude/pricing): Haiku 5.5 ($0.10/$0.50) about $0.38-0.78 per million, so about $1-4 one-off for this corpus; Sonnet 5.5 ($2/$10) about $6.8-10.8 per million, so about $20-48. Both are Claude credit spend. Batch and caching discounts combine. voyage-context-4 is a model-side alternative for embeddings only. Anthropic's skip-RAG threshold of 200k tokens is far below this corpus. Source: https://www.anthropic.com/news/contextual-retrieval
- Measured extraction test: pdftotext, pypdf, pdfminer (MarkItDown's backend, by my recollection) and PyMuPDF all produced identical corruption on one Damodaran slide file: 'CreaAon', 'EvaluaAng', 'AlternaAves', with 'ti' turned into 'A'. pdffonts shows subset fonts with no Unicode map, so switching text-layer extractors does not help, and keyword search would miss 'creation' there. It was 1 of 7 slide PDFs sampled. The three spring-2026 packets and the 5 sampled letter PDFs showed no such errors. A corruption check at ingestion, with vision or OCR for failing files, is what this suggests. Slide text also comes out fragmentary, with repeated footers. Source: https://pages.stern.nyu.edu/~adamodar/pdfiles/valonlineslides/session10.pdf
- PDF and slide options. Claude PDF support sends each page as text plus image: 1,500-3,000 text tokens per page plus image tokens, up to 600 pages per request (100 if context is under 1M), batch supported, paid by Claude credits; it can read charts. My rough estimate for 3,000 slide pages: $2-3 on Haiku 5.5. Docling: MIT, local, PDF and PPTX, OCR, chart understanding (https://github.com/docling-project/docling). MarkItDown: MIT, PDF and PowerPoint, OCR through a plugin (https://github.com/microsoft/markitdown). Marker: Apache code with OpenRAIL-M weights, free for personal use (https://github.com/datalab-to/marker). PyMuPDF: AGPL (https://github.com/pymupdf/PyMuPDF). LlamaParse: $1.25 per 1,000 credits, 10K credits on its free plan, 1-45 credits per page (https://developers.llamaindex.ai/python/cloud/general/pricing/). One valuation packet PPTX is about 142 MB. Source: https://docs.claude.com/en/docs/build-with-claude/pdf-support
- Vercel to Neon: both vendors recommend the pg driver with a module-level Pool and attachDatabasePool from @vercel/functions on Fluid compute, which is default for new projects since April 23, 2025 (https://vercel.com/docs/fluid-compute). Vercel adds a short idle timeout (about 5s), keep minimum pool size at 1, and do not set max to 1 (https://vercel.com/kb/guide/connection-pooling-with-functions). @neondatabase/serverless over HTTP is for platforms without pooling. Use the direct, non-pooler string for migrations. Open conflict: Neon warns against client-side pooling on a pooled string (https://neon.com/docs/connect/choose-connection), yet its Vercel example uses Pool on DATABASE_URL, which `neon env pull` makes the pooled string. Neon's page does not say which to use here. Source: https://neon.com/docs/guides/vercel-connection-methods
- Regions: Neon lists no India region; the closest listed is Singapore (https://neon.com/docs/introduction/regions). Vercel has both sin1 and bom1 but functions default to iad1, and Vercel says to run them in the same region as the data (https://vercel.com/docs/regions). Pinecone Starter is us-east-1 only, so pairing it with Neon in Singapore adds a cross-region hop to retrieval calls, while keeping both in the US moves everything away from the learner. Vercel Hobby is personal, non-commercial use only, with a 300s function maximum that covers streamed responses (https://vercel.com/docs/functions/limitations), so a multi-retrieval agent turn must finish inside that. Source: https://vercel.com/docs/regions

## Still unknown

- No evidence on the user's actual question: whether Haiku 5.5 teaches as well as Sonnet 5.5 when given good retrieval. The studies read measure retrieval or answer accuracy, not tutoring quality. A side-by-side test on real learner questions is the way to find out; the model is a single setting in code.
- No benchmark exists for this corpus with beginner questions. The gap between keyword-only, hybrid and reranked retrieval here is unmeasured; a small eval of 20-50 judged questions would settle it.
- Whether lakebase_vector and lakebase_text can be installed on the Neon Free plan. The docs read state no plan restriction, but only pgvector is explicitly confirmed on every plan. Not tested, to avoid creating resources.
- Storage figures are estimates. Actual index sizes have not been measured by loading data.
- search_result through Tool Runner was confirmed by reading SDK source only, not by a live API call. The Tool Runner docs prose does not name search_result.
- Whether search_result blocks pass through Claude Agent SDK custom tools or MCP tool results. The docs list other block types and do not mention citations.
- Voyage rate limits and access without a payment method, and whether a card is needed to use the free tokens in practice. The page describes Tier 1 as requiring a payment method.
- Gemini free-tier rate limits and whether OpenAI offers any free embedding allowance. Mistral OCR's price per 1,000 pages could not be read from its pricing page.
- Docling, Marker and Claude's PDF reading were not run on the corrupted slide, so whether they fix 'CreaAon' is unconfirmed. The 142 MB PPTX download timed out, so PPTX text quality is untested. Only 7 slide PDFs were sampled, so the corruption rate across all files is unknown.
- Corporate finance and investment philosophy lecture packets were not measured, and overlap between packets and webcast slides was not assessed.
- Copyright or reuse terms for storing Berkshire letters and Damodaran's material in a private RAG index were not established. No copyright statement turned up in the Damodaran pages or the 1990 letter page checked, which does not mean there are no restrictions.
- End-to-end latency from India (Neon Singapore versus US, Claude API routing) was not measured. Whether idle pooled connections delay Neon's scale-to-zero was not confirmed. Whether double pooling matters at one user is unresolved.
- Pinecone's handling of long-inactive Starter indexes: the pages checked mention no pausing, but no page states the policy either way.
