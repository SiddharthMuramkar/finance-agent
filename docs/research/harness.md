# Running the agent: Tool Runner, Managed Agents, Agent SDK

Research notes gathered on 2026-11-01. Prices, limits and terms change, so recheck before relying on them. This is not legal advice.

## Summary

All three can run claude-sonnet-5-5 with custom tools and take model and effort as settings, so the loop choice does not force the model decision now. The Tool Runner (beta) runs inside a Vercel function as a small library; you own SQL history, append-only replay, compaction and the 300 second limit. Managed Agents (beta) runs the loop and compaction at Anthropic, survives function restarts, and adds $0.08 per running hour plus a sandbox per session; text is buffered unless you opt into best-effort previews, and history sits outside SQL unless mirrored. The Agent SDK (0.x) spawns a 328 MB CLI subprocess with disk state; that exceeds Vercel's standard 250 MB Node limit, and Vercel documents it only inside a Vercel Sandbox, as experimental, with model calls through AI Gateway by default. Hosted code execution is stable, supports Sonnet 5.5, runs real Python with scipy and mpmath, cannot install packages, and is effectively free for one learner. It proves the arithmetic ran, not that the formula is right. Python on Vercel is GA, but no option here needs a Python backend.

## Options

### Tool Runner, TypeScript, in a Next.js route handler

- **Fit:** Loop runs: in your function (client.beta.messages.toolRunner). Vercel: fits a Hobby Node function; @anthropic-ai/sdk is 15.7 MB unpacked per npm, and each request is capped at 300 seconds including the stream. Streaming: stream: true gives one stream per model turn to forward as SSE, and runToolsEagerly starts tools during the reply. Custom tools: betaZodTool with a run function validated by Zod. Searching material and saving progress are plain functions; opening a chart can be a run function that writes a UI event to the same response and returns a short string (my design inference, no doc describes it). History and memory: yours, in SQL; read runner.params.messages after each step. Long conversations: compactBeforeNextTurn (beta) or threshold compaction, not both. Thinking rule: your job; freeze system and tools, append new context, replay assistant turns unchanged. Fees: none beyond tokens; caching must be requested with a top-level cache_control. Beta: runner, compaction and OTel are all beta. Tracing: SDK OpenTelemetry with no admin role.
- **What would break it:** A turn passing 300 seconds kills the in-memory runner unless every step was saved and the turn can resume. Re-rendering the system prompt from learner state, trimming old RAG results on the client, or changing tools mid-conversation returns a 400 on a default-enforced account. Losing thinking signatures in the SQL round trip does the same. Beta helper changes can break code, so pin the version. You also own more code than the hosted options, including resume logic.
- **Cost:** Tokens only: Sonnet 5.5 at $2 input, $10 output, $0.10 cache hits per MTok. Code execution and web search are priced separately. Vercel Hobby is free within quota.

### Tool Runner, Python, in a Vercel Python function or Services

- **Fit:** Loop runs: in your function (client.beta.messages.tool_runner). Vercel: anthropic 2.3.0 needs Python 3.10+; Vercel offers 3.12 to 3.14, streams by default, has a 500 MB bundle limit and the same 300 second Hobby cap. Streaming: stream=True, run_tools_eagerly=True. Custom tools: @beta_async_tool typed functions. History and memory: yours, in SQL. Long conversations: compact_before_next_turn or threshold compaction. Thinking rule: your job, same as TypeScript. Fees: none beyond tokens. Beta: same as TypeScript, plus Services (beta) if the Next.js UI and Python share one project. Tracing: SDK OpenTelemetry. Python-specific extra: MCP conversion helpers in anthropic.lib.tools.mcp, per the bundled guide.
- **What would break it:** Everything in the TypeScript option, plus a second runtime and deployment beside the Next.js UI. Services is beta, and a separate project adds cross-origin and auth work (my inference). Tool schemas and browser calculators can no longer share code (my inference).
- **Cost:** Same token cost as TypeScript, with no Anthropic fees beyond tokens. Function use counts against the same Hobby quotas (my inference; I did not verify how Services meters them).

### Claude Managed Agents

- **Fit:** Loop runs: on Anthropic's servers; your function sends events and reads SSE. Vercel: works from a Next.js route handler, and the session continues if a function ends, so you reconnect by opening a stream and listing history. Streaming: buffered agent.message per model request, or opt-in event_deltas previews, described as best effort. Custom tools: declared on the agent; the session pauses and your function posts user.custom_tool_result, and the TypeScript session tool runner automates this. History and memory: held by Anthropic until deleted; memory stores (beta) mount into the sandbox, or use your own SQL tools and mirror events for the UI. Long conversations: built-in compaction, surfaced as agent.thread_context_compacted. Thinking rule: handled, per Anthropic's page. Fees: $0.08 per running session-hour, idle free. Beta: the whole product, plus memory stores; not ZDR eligible. Tracing: Console session viewer, session usage totals, OpenTelemetry (admin role for API tracing). Budget: hard per-session cap in cents. Effort: model.effort.
- **What would break it:** Anthropic targets long-running async work, so buffered text or best-effort previews may feel poor in a live tutor chat (my inference; test it). Every session gets a sandbox this tutor may not need, and its latency is undocumented. A pending custom tool waits until a function is alive to answer it, so a timed-out function needs reconnect logic or webhooks. The SQL rule requires mirroring. Beta behaviour may change between releases.
- **Cost:** Tokens plus $0.08 per running hour; 100 running hours is $8 (my arithmetic). Container time is included. Web search is $10 per 1,000. Runs on the same credit as the API.

### Claude Agent SDK

- **Fit:** Loop runs: in a claude CLI subprocess your app spawns. Vercel: the 328 MB binary exceeds the 250 MB standard Node limit and is under the 500 MB Python limit. Running it inside a function is unproven by me, and Vercel documents it only inside a Vercel Sandbox driven by a function, as experimental. Streaming: includePartialMessages gives raw API events. Custom tools: in-process MCP server; built-ins can be limited with tools. History and memory: JSONL and CLAUDE.md on local disk, mirrored through a SessionStore, with a Postgres reference adapter available. Long conversations: automatic compaction, /compact and a PreCompact hook. Thinking rule: handled, per Anthropic's page. Fees: no Anthropic fee beyond tokens that I found; Sandbox or container hosting is separate. Beta: packages are 0.x (TypeScript 0.3.316, Python 0.2.176); traces are beta. Tracing: OTel metrics and logs via CLI env vars. Effort, a minimal default system prompt and maxBudgetUsd are options.
- **What would break it:** Bundle limit or subprocess failure in a Vercel function, per the open issue. Hobby Sandbox quotas pause creation when exceeded, and sessions cap at 45 minutes. Default AI Gateway routing may not draw on the Anthropic credit. Anthropic's 1 GiB per agent floor against Hobby's 2 GB function. Coding-agent machinery (shell, permissions, file tools) must be switched off for a tutor. A host outside Vercel would add a cost the credit does not cover.
- **Cost:** Tokens from the credit when using a Console API key, plus Sandbox or container hosting. Hobby Sandbox is free within 5 CPU-hours and 420 GB-hours a month. total_cost_usd is a client-side estimate, not billing data.

## Findings

- The Tool Runner is an SDK helper in beta. It runs tools when Claude calls them, handles the request and response cycle, manages conversation state and exits when a message has no tool call or max_iterations is reached. A thrown tool error goes back to Claude as is_error: true. So the loop is your process, not Anthropic's. Source: https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-runner
- With stream: true the TypeScript runner yields one BetaMessageStream per model turn. By default a reply's tools run after your loop body for that reply ends; runToolsEagerly: true starts each tool as soon as the model finishes writing its call. A tool that has started runs to the end even if the reply is cut short. Python has the same features as stream=True and run_tools_eagerly=True (https://github.com/anthropics/anthropic-sdk-python/blob/main/tools.md). Source: https://github.com/anthropics/anthropic-sdk-typescript/blob/main/helpers.md
- Vercel Hobby functions have a 300 second default and maximum for Node, Bun and Python. The limit includes time spent sending streamed responses, and overrunning returns a 504 FUNCTION_INVOCATION_TIMEOUT. Maximum memory is 2 GB. Uncompressed bundle limits are 250 MB, or 500 MB for Python; the large functions beta allows up to 5 GB on new projects with fluid compute. Hobby includes 4 active CPU-hours and 360 GB-hours of provisioned memory a month and is for non-commercial personal use (https://vercel.com/docs/plans/hobby), which is about 180 function-hours at 2 GB (my arithmetic). Source: https://vercel.com/docs/functions/limitations
- On claude-sonnet-5-5, if system, tools or earlier messages differ from what was sent when a thinking block was produced, that block and every later thinking block are invalid. Accounts created on or after August 31, 2026, 00:00 UTC get a 400 error by default, and Anthropic says to go append-only on any account. Nothing changes if Managed Agents or the Agent SDK builds the requests. A saved session must replay exactly what was sent and received (JSON formatting and key order do not matter, values do), and must not be re-rendered from inputs such as the date or updated instructions. Changing context goes in a new turn or an appended role: system message. prefix_mismatch_behavior: drop_block works on Sonnet 5.5 only with adaptive thinking and raises output tokens, and Anthropic calls fixing the edit the better long-term solution. Source: https://platform.claude.com/docs/en/build-with-claude/preserved-thinking
- Server-side compaction does not count as a prefix edit. On-demand compaction (beta compact-2026-09-04) lets kept turns keep their thinking under stated conditions; the runner sends the request when you call compactBeforeNextTurn / compact_before_next_turn, and you must add the beta yourself. Threshold compaction (beta compact-2026-01-12, default trigger 150,000 input tokens, minimum 50,000; https://platform.claude.com/docs/en/build-with-claude/compaction-threshold) does not keep thinking in reinserted turns. Use only one kind on a runner. A hand-written summariser that keeps recent turns with their thinking fails the check. Source: https://platform.claude.com/docs/en/build-with-claude/compaction
- Managed Agents is beta on every model and supports claude-sonnet-5-5. Anthropic hosts the harness, with built-in prompt caching and compaction, and positions it as best for long-running tasks and asynchronous work, while the Messages API is best for custom loops and fine-grained control. It is not eligible for zero data retention. Each session gets its own sandbox (https://platform.claude.com/docs/en/managed-agents/environments), and the sandbox starts provisioning as soon as the session is created (https://platform.claude.com/docs/en/managed-agents/sessions). Source: https://platform.claude.com/docs/en/managed-agents/overview
- Managed Agents bills tokens plus session runtime at $0.08 per session-hour, measured to the millisecond and only while status is running. Idle, rescheduling and terminated time is free, and runtime replaces code execution container billing. Web search is $10 per 1,000. 100 running hours would be $8 (my arithmetic). A session can carry a hard budget in US cents (https://platform.claude.com/docs/en/managed-agents/sessions). Source: https://platform.claude.com/docs/en/about-claude/pricing
- By default Managed Agents response text arrives as buffered agent.message events, each emitted only after its model request completes. Live text needs the opt-in event_deltas[] query parameter on the stream, and those previews are described as a best-effort display aid. A stream delivers only events emitted after it opens; to reconnect you open a new stream, list the event history and de-duplicate by ID (https://platform.claude.com/docs/en/managed-agents/events-and-streaming). Source: https://platform.claude.com/docs/en/managed-agents/event-deltas
- A Managed Agents custom tool call arrives as agent.custom_tool_use. The session pauses at session.status_idle with stop_reason requires_action, your code runs the tool and sends user.custom_tool_result, and a client can answer without waiting for the idle event. After a reconnect, stop_reason.event_ids lists the calls still owed. The TypeScript SDK has client.beta.sessions.events.toolRunner, which handles stream reconnect and result posting (https://github.com/anthropics/anthropic-sdk-typescript/blob/main/helpers.md). Source: https://platform.claude.com/docs/en/managed-agents/events-and-streaming
- Managed Agents stores history server-side, and transcripts persist until you delete them. Sessions start with fresh context unless a memory store is attached. Memory stores are beta (agent-memory-2026-07-22), need the agent toolset, mount as a directory in the sandbox and hold up to 10,000 memories each, with every change versioned. Keeping the project's rule that stored data lives in SQL means custom tools to SQL plus mirroring events for the UI (my inference). Source: https://platform.claude.com/docs/en/managed-agents/memory
- Vercel publishes two Managed Agents guides. One holds the /api/chat response open for 1 to 3 minute research turns and says the 300 second default covers a typical turn. The other (https://vercel.com/kb/guide/claude-managed-agent-vercel) uses a Next.js app, Neon and a durable Workflow that polls events every 3 seconds; Hobby includes 50,000 Workflow events a month (https://vercel.com/docs/workflow/pricing). Polling delivers finished events, not live tokens (my inference). Source: https://vercel.com/kb/guide/claude-managed-agents-vercel-services
- The Agent SDK spawns and supervises a claude CLI subprocess that owns a shell, working directory and JSONL transcripts on local disk; Anthropic says hosting it is not like hosting a stateless API wrapper. The suggested starting point is 1 GiB RAM, 5 GiB disk and 1 CPU per agent, with 1 GiB called a floor. Resuming across hosts needs a SessionStore adapter (a mirror, not a replacement), and the repos ship a Postgres reference adapter (https://code.claude.com/docs/en/agent-sdk/session-storage). Source: https://code.claude.com/docs/en/agent-sdk/hosting
- The Agent SDK's Linux binary is 328,262,589 bytes unpacked per npm metadata for @anthropic-ai/claude-agent-sdk-linux-x64@0.3.316. The Python wheel claude-agent-sdk 0.2.176 unpacks to 328.8 MB (I measured the wheel). That exceeds Vercel's 250 MB standard Node limit and sits under the 500 MB Python limit. A user report still open when fetched, https://github.com/anthropics/claude-agent-sdk-typescript/issues/329, describes the same failure on Vercel at a smaller 230 MB binary and says there is no documented workaround. Source: https://www.npmjs.com/package/@anthropic-ai/claude-agent-sdk-linux-x64
- Vercel's documented route for the Agent SDK is durable-harness, marked experimental. It runs the claude CLI only in a Vercel Sandbox, with no Claude Code in the function, and by default sends model calls through AI Gateway with an OIDC token rather than an Anthropic API key. Hobby Sandbox quotas are 5 active CPU-hours, 420 GB-hours of memory and a 45 minute maximum session, and creation pauses when quotas run out (https://vercel.com/docs/sandbox/pricing). Source: https://vercel.com/docs/agent-harnesses/claude-code
- Agent SDK custom tools are defined with tool() or @tool and wrapped in an in-process MCP server. A tools array limits which built-ins Claude sees. Streaming needs includePartialMessages, which yields raw API events (https://code.claude.com/docs/en/agent-sdk/streaming-output). The SDK compacts automatically and emits compact_boundary (https://code.claude.com/docs/en/agent-sdk/agent-loop). Options include effort, a minimal default system prompt and maxBudgetUsd, which uses a client-side estimate that can overshoot (https://code.claude.com/docs/en/agent-sdk/typescript). Source: https://code.claude.com/docs/en/agent-sdk/custom-tools
- Claude API OpenTelemetry is beta. SDK tracing needs no special role and is the only single route that covers client tools run by the Tool Runner (spans anthropic.messages.tool_runner and anthropic.custom_tool_use). API tracing needs the Console admin role and covers Managed Agents turns and server tools. Managed Agents also has a no-code Console session viewer with cost (https://platform.claude.com/docs/en/managed-agents/session-observability). Agent SDK telemetry goes through the CLI, with traces in beta behind CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1 (https://code.claude.com/docs/en/agent-sdk/observability). On Hobby, drains are unavailable (https://vercel.com/docs/drains) and runtime logs last 1 hour (https://vercel.com/docs/logs/runtime), so keeping traces means an outside OTLP backend or your own usage rows in SQL (my inference). Source: https://platform.claude.com/docs/en/manage-claude/opentelemetry
- The code execution tool is marked stable, needs no beta header and supports claude-sonnet-5-5. It runs Python 3.11 on 1 CPU with 5 GiB RAM, with pandas, numpy, scipy, statsmodels, sympy and mpmath. There is no internet and no installing packages, so only pre-installed libraries are available; numpy-financial is not listed. The bundled guide's claim that pip install works is out of date. Results arrive whole after a pause in the stream, and containers expire after 30 days. The runner accepts raw server tool definitions and never runs them itself, and it resumes pause_turn (https://github.com/anthropics/anthropic-sdk-typescript/blob/main/helpers.md). This gives executed arithmetic, but a wrong formula written by the model would still give a wrong answer, and the docs do not address decimal rounding for money (my inference). Source: https://platform.claude.com/docs/en/agents-and-tools/tool-use/code-execution-tool
- Code execution pricing: free beyond tokens when web_search_20260209 or web_fetch_20260209 (or later) is in the request. Otherwise 1,550 free hours per organization per month, then $0.05 per hour per container, with a 5 minute minimum per execution. If files are attached, time is billed even when the tool is not called. 1,550 hours at the 5 minute minimum is 18,600 runs a month (my arithmetic). Tokens for the code and its output are still charged. Source: https://platform.claude.com/docs/en/about-claude/pricing
- Python on Vercel became generally available on October 15, 2026, with FastAPI detection, on Fluid compute. Python functions stream (https://vercel.com/docs/functions/runtimes/python). Services, in beta on all plans, deploys a Next.js frontend and a FastAPI backend in one project with shared routing and env vars (https://vercel.com/docs/services). The TypeScript and Python Tool Runners offer the same core features, so the runner does not decide the language. Points for one TypeScript app are my inference: browser calculators are TypeScript anyway, Zod schemas can be shared, and there is one runtime to deploy. Points for Python are also inference: finance libraries, which hosted code execution already provides inside the loop, and ingestion scripts, which can run outside the app. Source: https://vercel.com/changelog/python-on-vercel-is-now-generally-available
- Model and effort are settings in every option, so the loop does not lock them in. Tool Runner uses a per-request model and output_config.effort; Managed Agents uses model.effort on the agent or a per-session override (https://platform.claude.com/docs/en/managed-agents/sessions); Agent SDK uses model and effort options. Sonnet 5.5 defaults to high effort, and Anthropic suggests starting at medium for well-specified multistep tool use. Live prices per MTok: Sonnet 5.5 is $2 input, $10 output, $0.10 cache hits (the bundled guide's $0.20 is out of date); Haiku 5.5 is $0.10 / $0.50 up to 100,000-token prompts and $0.50 / $2.50 above (https://platform.claude.com/docs/en/about-claude/pricing). Moving a live conversation from Sonnet 5.5 to Haiku 5.5 drops Sonnet's reasoning without error; Haiku 5.5 to Sonnet 5.5 keeps it on the Claude API (https://platform.claude.com/docs/en/build-with-claude/preserved-thinking). Credits: the $200 Ultra credit covers the Messages API, Managed Agents and the Agent SDK, does not roll over, and API requests stop when it runs out unless purchased credits or auto-reload exist (https://support.claude.com/en/articles/17154008-monthly-api-credits-for-max-ultra-and-team-plans). Source: https://platform.claude.com/docs/en/build-with-claude/effort

## Still unknown

- When the learner's Console organization was created. Before August 31, 2026 the prefix check is not enforced by default, but Anthropic says to build append-only either way.
- How long a real tutor turn takes on Sonnet 5.5 at medium effort with RAG, charts and code execution. Whether 300 seconds is enough has not been measured; Vercel only quotes 1 to 3 minutes for its research demo.
- Sandbox provisioning latency for Managed Agents, and whether a custom-tools-only agent can avoid or reduce the sandbox. Docs say each session gets one and provisioning starts at session creation.
- Whether Managed Agents compaction can be tuned, such as a threshold or summary instructions. I found only the event and the overview statement.
- Whether event_deltas previews feel good enough for a tutor chat. This needs a hands-on test.
- Whether the Agent SDK CLI actually runs inside a Vercel function using the large functions beta or the 500 MB Python limit, given the subprocess and writable-disk needs. I did not test this and did not verify Vercel's filesystem rules.
- Whether durable-harness can use a Console API key instead of AI Gateway, and whether AI Gateway usage could draw on the Anthropic credit. The credit article does not mention AI Gateway.
- Whether the Python SDK has an equivalent of client.beta.sessions.events.toolRunner. I confirmed it only in the TypeScript helpers.
- Message threads (client.beta.messages.thread, beta), which keep the conversation on the server, appear in the TypeScript helpers, but I found no docs page. Their retention and interaction with preserved thinking are unverified.
- Whether the Agent SDK can use the hosted code execution server tool. I did not find this documented.
- Whether Sonnet 5.5 will reliably use Decimal or correct rounding in code execution unless told to, and whether a cheaper model such as Haiku 5.5 teaches well enough with RAG. No primary source settles either; both need evals on the project's own questions.
- How Vercel Services meters Hobby quotas across a Next.js and a Python service in one project.
